# Close the safety gaps, then build

The Fisker Ocean port has more to gain from correcting what it already ships than from adding features: the research found seven safety-relevant defects or exposures in the local code, and each has a known fix. Panda never sets `gas_pressed`, so it accepts a live accel request on 0x121 while the driver is on the accelerator; the `ICC_0x35B` override table holds APA activation, remote automated parking and trained parking asserted on every drive; a steering-capable HTTP server listens on all interfaces whenever the device is in a car; the stop-sign direction filter answers YES for `stop=all` nodes that belong to the opposing approach; and the model-confirmation signal cannot fire during an approach because `shouldStop` is defined only below 0.3 m/s. Beyond corrections, the largest untapped asset is the car itself: the ADAS ECU already publishes speed-limit recognition, traffic-light and forbidden-sign data, an ADASIS map horizon, driver monitoring, 16 ultrasonic ranges and its own diagnostics on the bus the comma taps, and none of it reaches openpilot. Longitudinal is finishable, but the port is the only one in opendbc that hands a signed accel frame back and forth mid-drive, so it pays a continuity cost that every other port avoids by blocking the stock frame permanently. The recommended order is: safety corrections (all offline), a read-only signal survey, the standard panda test classes, then longitudinal continuity, cancel and standstill, with fault-threshold work last. Effort and risk ratings in the roadmap are this report's judgement; everything else is cited. Local paths are under `/Users/hiremanirmss/Fisker/sunnypilot`.

## Seven corrections come before any new feature

**Panda does not track the accelerator.** The Fisker RX hook sets `brake_pressed` and `vehicle_moving` but contains no assignment to `gas_pressed` ([fisker.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/fisker.h)). Common safety defines longitudinal permission as `controls_allowed && !gas_pressed_prev`, and a frame passes only if that is true and accel is in range, or accel equals the inactive value ([longitudinal.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/longitudinal.h)). With the flag never set, panda accepts non-inactive accel while the driver presses gas. Every other longitudinal port closes this with a pedal read from a counter- and checksum-validated message, as Tesla, Rivian and VW MEB show ([tesla.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/tesla.h), [rivian.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/rivian.h), [volkswagen_meb.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/volkswagen_meb.h)). The gap went unnoticed because every class in `test_fisker.py` derives from `unittest.TestCase` instead of `common.CarSafetyTest` and `LongitudinalAccelSafetyTest`, whose `test_no_disengage_on_gas` and `test_prev_gas` exist to catch it ([test_fisker.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/tests/test_fisker.py), [common.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/tests/common.py)). The gap also bears on the one logged plausibility fault: driver or one-pedal torque adding to a still-active request is one of four candidate causes.

**The 0x35B table holds parking functions asserted.** The override dict is non-empty and active: it forces `ICC_APAActivation = On`, APA enabled, park-out directions, remote automated parking enabled and trained parking enabled on every frame, and the code comment itself warns that APA activation is a momentary user action that stays asserted when overridden ([values.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/fisker/values.py)). The same table already produced one silent regression, when a pinned blind-spot value made the ADAS report BSD Off for a whole drive on 2026-11-02. This reads as a leftover experiment. Strip the table to the entries a feature needs (lane-change assist, auto high beam) and pass everything else through.

**A steering input is exposed on the network.** `remote_control_server` runs whenever the device is in a car and serves HTTP on 0.0.0.0:8899; the controller substitutes the phone's angle when `RemoteControlEnabled` is set, the update is under 300 ms old and speed is under 10 mph, with the cap raised to ±250° ([carcontroller.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/fisker/carcontroller.py), [process_config.py](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/system/manager/process_config.py)). It has no obstacle check, although the car publishes 16 ultrasonic ranges in `ADAS_0x352` ([world.dbc](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/third_party/webhud/dbc/fisker_ocean_adas_world.dbc)). The Ocean's cloud API was shown in May 2025 to accept raw CAN from anyone holding a VIN and an exposed key, so this platform's history argues for caution ([TechTimes](https://www.techtimes.com/articles/320358/20260713/comma-ai-delivers-hands-free-driving-fisker-ocean-via-openpilot-port.htm)). Make the process opt-in at manager level, bind it to private addresses as the web HUD already does, and gate motion on ultrasonic clearance and driver occupancy.

**`stop=all` is not a junction-node marker.** The OSM wiki tells mappers to put `stop=all` on every per-approach node of a detailed all-way stop ([Tag:highway=stop](https://wiki.openstreetmap.org/wiki/Tag:highway%3Dstop)). In a 9,871-node San Jose sample, 291 of 764 `stop=all` nodes (38%) carried `direction=forward` or `backward` (own measurement via [Overpass API](https://overpass-api.de/api/interpreter)). The current rule "stop=all: always YES" therefore stops the car for the opposing approach's node just after it clears the junction on an undivided road. An explicit forward/backward on a single-way node must outrank `stop=all`.

**The confirmation signal cannot confirm.** `should_stop` is `v_ego < 0.3 and a_target < 0.1`, a standstill-hold flag that is false by construction while the car moves ([drive_helpers.py](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/selfdrive/controls/lib/drive_helpers.py)). Stop Sign Assist only coasts until `model_wants_stop`, which is that flag or `min(velocity.x) < 1.5 m/s` ([stop_sign_controller.py](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/sunnypilot/selfdrive/controls/lib/stop_sign/stop_sign_controller.py)). The fix is in the stop-sign section below.

**The stop target must be zero.** NHTSA recall 22V-037 treated a deliberate roll through all-way stops at up to 5.6 mph as a defect across 53,822 vehicles with no reported incidents ([NHTSA](https://static.nhtsa.gov/odi/rcl/2022/RCLRPT-22V037-4462.PDF)). A model trained on drivers who roll must not be allowed to veto a map-prior stop, and no "rolling stop" option belongs in this feature.

**Disengage leaves the car's ACC running.** Panda derives `controls_allowed` from the car's cruise state, so if openpilot disengages while the stock ACC stays active, panda still permits control ([fisker.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/fisker.h)). Every upstream port with stock-state engagement has a cancel path.

Four smaller items belong in the same pass. `fisker.h` honours the longitudinal flag on release builds where Toyota SecOC, Tesla, Rivian and Hyundai CAN-FD gate it behind `ALLOW_DEBUG` ([toyota.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/toyota.h)), and `launch_env.sh` exports `SKIP_FW_QUERY=1` for every brand. Comments disagree on whether `ADAS_LgtCtrl_Typ` must be 1 or 2 for deceleration, so decel authority is unverified ([fiskercan.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/fisker/fiskercan.py)). `VCU_ACCRdy`, the signal that dropped in the plausibility fault, is decoded but its use as a disengage trigger was not confirmed. And the docstring that describes compass values as a travel bearing states the reverse of the documented convention.

## Fisker is the only port that hands accel back mid-drive

Every upstream port that keeps the stock module on the bus switches at safety-mode init: once the longitudinal flag is set, the stock accel frame is statically blocked for the whole drive and openpilot transmits continuously with inactive values. Toyota (including SecOC), Rivian, Hyundai CAN-FD camera-SCC, VW MQB and MEB, GM and Honda radarless all work this way; Tesla and Honda Nidec add a dynamic exception for stock AEB ([safety.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/safety.h), [rivian.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/rivian.h)). None blocks on `controls_allowed` and none uses a time-since-TX relay. That is why none needs counter alignment, and why Toyota SecOC gets away with a counter that restarts at 0 on each reset-counter change ([toyota/carcontroller.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/toyota/carcontroller.py), [opendbc#1385](https://github.com/commaai/opendbc/pull/1385)). No upstream precedent exists for a mid-drive handover of a signed accel frame, so receiver tolerance for a gap or duplicate at the transition is unknown.

**Handover and counters.** The port faces a real choice. Option A adopts the upstream pattern: block 0x121/0x117/0x118 permanently while the flag is set and send valid standby frames all drive. The handover problem disappears, at the price of losing stock ACC as a fallback and of owning the ESP handshake continuously; the controller already notes that silence drops the ESP into "AEB unavailable" ([carcontroller.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/fisker/carcontroller.py)). Option B keeps the relay and makes it continuous. For signed 0x121, reuse the lateral candidate-substitution already proven on 0x1D0. For plain-E2E 0x117/0x118, use the VW/GM modify-and-forward pattern: panda rewrites fields of the OEM frame and recomputes the CRC, which keeps the OEM counter by construction ([mqbcan.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/volkswagen/mqbcan.py)). Panda already does this for 0x317, 0x514, 0x362 and 0x52A. This report recommends Option B: it preserves the car's own ACC, which holds the radar fusion, hydraulic brakes and recall-fixed software, and it reuses mechanisms already tested on this car.

**AEB passthrough.** Because openpilot's 0x118 replaces the frame that carries AEB activation, adopt Tesla's rule: parse the OEM 0x118 on bus 2 as a validated RX check, and when the OEM asserts AEB, forward its frame and reject openpilot's on the same boolean ([tesla.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/tesla.h)). The existing time-based relay does not provide this.

**Gas override and cancel.** After panda tracks gas, the controller must send the inactive value while overriding. If the VCU wants a distinct override status, copy MEB's exception, which is keyed on `controls_allowed` and zero accel, deliberately not on longitudinal permission ([volkswagen_meb.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/volkswagen_meb.h)). For cancel, the precedents are a field in the long frame (Tesla, Toyota), a status spoof with a required two-step sequence (Rivian), and a delayed cancel so braking does not fault the ECM (GM, Hyundai) ([rivian/carcontroller.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/rivian/carcontroller.py), [gm/carcontroller.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/gm/carcontroller.py)). The delay matters here: every ACC switch-off on the Ocean already passes through `Failure_irreversible` for 20-40 ms. The existing East-to-cancel forward rewrite is the natural carrier.

**Standstill.** The nearest analogue is VW MEB, another EV with an ESP-side handshake: request hold while `longControlState == stopping`, wait for ESP hold confirmation, switch accel to inactive, and leave through an explicit drive-off state. MEB's lessons are that the release faults, not the hold (hold to no-request "causes the car to fault into park" without a ramp state), and that the drivetrain acts on hold requests with ACC off, so panda allows hold and drive-off only with `controls_allowed`, never park, and release always ([mebcan.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/volkswagen/mebcan.py), [volkswagen_meb.h](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/safety/modes/volkswagen_meb.h)). The 2026-11-13 commit forbids all such requests, so this is a deliberate, gated reversal that needs MEB-style tests. Measure first whether the car holds itself: OS 2.0 added automatic vehicle hold ([InsideEVs](https://insideevs.com/features/707709/fisker-ocean-v2-ota-no-adaptive-cruise-control/)), and Tesla and Rivian need no hold request at all, with Tesla reporting `cruiseState.standstill = False` so resume needs nothing special ([tesla/carstate.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/tesla/carstate.py)). Which signal makes the Fisker ESP take the hold is unknown.

**The plausibility fault.** The +1.0 m/s² cap rests on one route in which the car faulted after accelerating about 1.5 m/s² for 0.6 s, 0.4-0.6 above the request ([values.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/fisker/values.py)). The fault was a mismatch, not a range violation, so the cap shrinks it without addressing it. Upstream shows stock controllers monitor the request stream's plausibility: Tesla faults at 5.0 m/s³ jerk and ships 4.9, found by bisecting with the Longitudinal Maneuvers tool ([opendbc#1648](https://github.com/commaai/opendbc/pull/1648)); VW carries an explicit deviation band and jerk gradients. Test four hypotheses against the log: driver or one-pedal torque on top of an active request; jerk fields in 0x118 inconsistent with 0x121; a step the powertrain could not follow, which Toyota handles with ±4 m/s³ rate limits and predicted-error feedback; and a counter discontinuity freezing the old request. No source documents the Fisker monitor. Separately, cars without the recall software lose regen for about 740 ms over bumps ([Green Car Reports](https://greencarreports.com/news/1144223_fisker-ocean-recalled-due-to-regen-brake-issue)), and because the port forbids hydraulic requests, a decel request is under-delivered exactly then. Keep following gaps conservative and log `VCU_RegenLvlFb` and software versions per route.

**Tests.** Move the suite onto `CarSafetyTest` and `LongitudinalAccelSafetyTest` first, because doing so changes what panda permits. Two overrides are needed: `test_fwd_hook` assumes static blacklisting, and `RELAY_MALFUNCTION_ADDRS` must list 0x121, 0x117, 0x118, 0x1D0 and 0x1C0 on bus 0.

## Stop signs need a new rule order and a model signal that leads

**The forward/backward reading is correct; five other rules change.** Four wiki pages agree that on a way node `direction=forward` means traffic travelling in the way's node order must stop ([Tag:highway=stop](https://wiki.openstreetmap.org/wiki/Tag:highway%3Dstop), [Key:traffic_sign:direction](https://wiki.openstreetmap.org/wiki/Key:traffic_sign:direction)). That covers about 86% of stop nodes globally and 84% in California, where 88.1% of 239,312 stop nodes carry a direction ([taginfo California](https://taginfo.geofabrik.de/north-america:us:california/tags/highway=stop#combinations)). The changes are as follows. First, explicit forward/backward outranks `stop=all`. Second, `direction=both` means the node applies to all approaches, as Valhalla and iD treat it; the filter currently returns UNKNOWN for a value on 4.3% of California nodes ([valhalla graph.lua](https://github.com/valhalla/valhalla/blob/master/lua/graph.lua)). Third, read `stop:direction` and `traffic_sign:direction` as fallbacks. Fourth, resolve an untagged mid-way node with the nearest-junction rule instead of UNKNOWN: travel toward the nearer way end matched explicit tags on 97.3% of 5,969 testable San Jose nodes (own measurement), and OSRM ships a 20 m version ([osrm car.lua](https://github.com/Project-OSRM/osrm-backend/blob/master/profiles/car.lua)). A stop node met just after a junction belongs to the opposing approach. Fifth, keep the rank-based inference for bare junction nodes; it matches OSRM's `stop=minor` logic.

**Keep compass values disabled.** The wiki defines degree and cardinal values as the direction a sign faces, against travel, and documents them only for nodes beside the road ([Key:direction](https://wiki.openstreetmap.org/wiki/Key:direction), [Key:traffic_sign](https://wiki.openstreetmap.org/wiki/Key:traffic_sign)). Real data contradicts itself by value type: among 3,843 testable nodes, degree values were 89% facing while cardinal letters were 69% travel (own measurement). Neither OSRM nor Valhalla interprets them. They are 0.29% of stop nodes globally and about 0.08% in California, so UNKNOWN costs almost nothing. `COMPASS_DIRECTIONS_TRUSTED = False` was right; accept a compass value only when it agrees with the geometric answer.

**Traffic signals follow a four-case rule.** A signal on a junction node applies to every approach. A mid-way node with `traffic_signals:direction`, which outranks plain `direction`, applies by node order. A mid-way node on a one-way applies. An undirected mid-way node on a two-way road takes the nearest-junction default ([Tag:highway=traffic_signals](https://wiki.openstreetmap.org/wiki/Tag:highway%3Dtraffic_signals)). Only 40.7% of signal nodes globally carry the tag, though California reaches 62.2% ([taginfo](https://taginfo.openstreetmap.org/tags/highway=traffic_signals#combinations)).

**Fixing the confirmation signal.** The model has no stop-sign, light or stop-line output; `modelV2.action` carries only curvature, acceleration and `shouldStop` ([log.capnp](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/cereal/log.capnp)). Forks infer intent from plan shape with horizon-scaled tests. sunnypilot DEC compares `position.x[32]` to an expected distance of 32 m at standstill rising to 165 m at 60 km/h and fires on filtered urgency above 0.24 ([dec.py](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/sunnypilot/selfdrive/controls/lib/dec/dec.py)). FrogPilot treats a planned minimum speed at or below 70% of ego speed, or below 1.0 m/s at 0.5-1.5 s, as stopping, through a 1.5 s filter with lead exclusion; its Force Stop then latches the stop distance after 0.5 s so a model that changes its mind cannot cancel it ([frogpilot_vcruise.py](https://raw.githubusercontent.com/FrogAi/FrogPilot/FrogPilot/frogpilot/controls/lib/frogpilot_vcruise.py)). The fixed 1.5 m/s threshold is the outlier, and it explains why a 2.4 mph roll-through never confirmed.

The report recommends three steps. Verify first: plot `velocity.x[0]`, `min(velocity.x)` and `vEgo` around the logged sign to learn whether the test never fired or fired after the sign was released. Then replace the test with a weak, early confirmer (endpoint shortfall or planned-speed ratio, excluding relevant leads) that arms braking, and latch it. Tune by labelling each map-sign pass from `carState` as full stop, rolling stop, slow-through or no response, and require confirmation before the braking point, `v²/(2·1.0) + v·1.0` metres ahead of the stop point. Shadow data flatters the model, because its plan follows the driver's braking; score only passes where the signal leads the first brake application. Thresholds do not transfer across model generations. The longer-term design is the one Tesla documented in 2020: the map decides, the car stops, and the driver taps the accelerator to proceed ([Tesla manual](https://www.tesla.cn/ownersmanual/modely/en_gb/GUID-A701F7DC-875C-4491-BC84-605A77EA152C.html)). Direction filtering becomes the false-positive control, with an early "stopping for stop sign" announcement at coast start. No fork implements automatic creep or all-way turn-taking, and none should be attempted here. The fixed 6 m margin is a guess at the sign-to-line offset; the model's own predicted stop point can refine it. For turns, Lane Turn Desire remains the only supported form, since upstream removed navigation input in 0.9.7 ([openpilot 0.9.7](https://blog.comma.ai/097release/)); a stop followed by a turn exercises the 30° divergence override that already needed an exception.

## The car already computes what the port lacks

The FM29 matrix shows the ADAS ECU publishing far more than Fisker exposed, and all of it is already decoded and streamed to the web HUD ([world.dbc](/Users/hiremanirmss/Fisker/sunnypilot/openpilot/third_party/webhud/dbc/fisker_ocean_adas_world.dbc), [Oceanscape](https://github.com/moistpope/oceanfront-view)). `ADAS_0x311` carries the recognised speed limit for Speed Limit Assist. `ADAS_0x334 ADAS_FobdSign` and the `0x210`/`0x351` traffic-light state and distance offer an independent confirmer or veto for Stop Sign Assist. `ADAS_0x481/0x482` report per-ECU E2E and invalid-signal faults, which would show at once when a relayed frame upsets the ADAS ECU, something inferred today from cluster symptoms. `ADAS_0x659` gives the ADAS firmware version, which matters because FOA's Marlin installs ship "ADAS 3.1.1" and fleet software is heterogeneous ([FOA timeline](https://fiskeroa.com/?p=446)). The radar's `Class`, `DynProp` and `ArelLong` fields are discarded although radard needs model confirmation precisely because the MRR reports gantries and curbs as stationary cars ([radar_interface.py](/Users/hiremanirmss/Fisker/sunnypilot/opendbc_repo/opendbc/car/fisker/radar_interface.py)). Which signals are populated on shipped firmware is unknown; TLR, hands-on detection and the ADASIS horizon may be inactive, and a UK car sent blank ADASIS metadata. A populated-signal survey over existing routes comes first.

Because the stock ADAS stays alive behind the panda, the port has an option few others have: let the car's ACC keep the brakes while the comma shapes its inputs. sunnypilot's sanctioned mechanism is ICBM, which presses cruise buttons so SLA and Smart Cruise Control work without openpilot longitudinal; no Fisker `icbm.py` exists ([ICBM doc](https://community.sunnypilot.ai/t/intelligent-cruise-button-management/244)). Whether the port's current speed path already does this by another route was not determined, and cancel, resume and gap buttons remain "TBD from bench testing". ICBM cannot hold at a stop sign, so it complements longitudinal instead of replacing it.

Against other forks the checkout lacks little. Usable now on stock ACC are FrogPilot's louder blind-spot alert, blind-spot path, speed-limit-changed chime, Pause Steering Below and minimum lane-change speed, and dragonpilot's radar-track and lead-stat overlays, which suit the radar tap ([FrogPilot README](https://raw.githubusercontent.com/FrogAi/FrogPilot/FrogPilot/README.md), [dragonpilot changelog](https://raw.githubusercontent.com/dragonpilot-community/dragonpilot/pre-build/CHANGELOGS.md)). Almost no fork lateral work applies to angle steering. The most valuable upstream tools are already in the tree: the lateral maneuver report needs only a manually set ACC speed, so it can replace the first-cut `steerRatio = 15.0` now ([comma blog 0.11.1](https://blog.comma.ai/0111release/)). Everything in the forks' longitudinal groups (Conditional Experimental Mode, Force Stop, personalities) presupposes openpilot longitudinal. One paraphrased reading of upstream's unreleased 0.11.3 notes says "Autospeed" becomes always-on; that entry is unverified, but if accurate it raises the value of finishing Fisker longitudinal.

Three risks need recording. The EPS 0x1C2 spoof stays disabled because it raised ADAS errors, and the LCA/TJA lateral type raises a DTC; both are bench work. Cluster rewrites are medium risk, since the ADAS logged a DTC when its settings frame was disturbed. New actuator requests (haptic, turn lamps, VCU remote driving) are the highest risk. Finally, no shareable route exists for CI while at least four developer lines cross-merge handover code, with over 30 SecOC and handover commits in six weeks.

## Conclusion

The research reframes the port's position. Its lateral path is mature and its longitudinal path is not unfinished so much as architecturally unusual: the choice to keep the stock ACC alive is what makes handover hard, and it is also the port's best asset, because it keeps a recall-fixed controller with hydraulic brakes one relay timeout away. The right goal is therefore not parity with Tesla or Rivian longitudinal but a clean split in which openpilot owns the request only while its stream is provably continuous and the car's AEB can always preempt it.

The second shift concerns where information comes from. The stop-sign work treated the map as a prior and the driving model as the judge, but the model has no concept of a stop sign and was trained on drivers who roll. A better arrangement makes the map the decision-maker once its direction rules are fixed, the driver the release, and the car's own camera, which nobody has yet used, the independent witness. What remains unknown is mostly measurable from data already on disk: which FM29 signals are live, whether the 1.5 m/s test ever fired, and whether the car holds itself at zero. Those three answers decide most of the roadmap's second half.
